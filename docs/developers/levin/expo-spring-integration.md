# WiseEASE — интеграция Expo и Spring

Ветка `codex/levin-expo-spring-integration` основана на `main` с уже слитым Spring-бэкендом (PR #6). Фронтенд взят из `main` после PR #5. Цель — проверить существующий сценарий Марии и Никиты, сохранив экраны команды.

## Что подключено

- Существующий выбор роли открывает Spring-сессию демоаккаунта. Zustand применяет снимок после действий и запрашивает `GET /state` каждые 1,5 секунды при активном приложении.
- Мария видит баланс и историю и может отправить перевод знакомому получателю. Никита видит заявку в семейном разделе, может одобрить или отклонить её, изменить порог и проверку новых получателей. Статус и баланс Марии обновляются без ручного обновления.
- В `GET /state` добавлен `accountBalance` для собственного баланса вошедшего аккаунта. Для Никиты `balance` по-прежнему `null`: защищаемый остаток видит Мария.

## Что нужно для согласованного MVP

| Сценарий | Spring | Следующий шаг в Expo |
| --- | --- | --- |
| Вход по email и паролю | Есть | Подключить форму к существующему входу. |
| Новый получатель | Есть поиск по Wise ID | Заменить ввод имени и IBAN вводом Wise ID; показывать имя из результата поиска. |
| История получателей и причины одобрения | Есть список успешных получателей, причины в предпросмотре и заявке | Рендерить список из API вместо встроенных контактов. До подтверждения показывать конкретную причину или обе причины. |
| Денежный запрос Марии | Есть список разрешённых людей, его изменение Никитой и создание запроса | Связать экран запроса со списком `requestPeople` и созданием запроса. Никите дать редактировать список. Получение и оплата денежного запроса не входят в демо. |
| Help и правила Марии | Есть порог и проверка новых получателей; изменять их может только Никита | Показывать Марии оба правила только для чтения и оставить звонок в Help. Текст про 24 часа убрать: проверка новых получателей отключается сразу. |

## Где нужен новый бэкенд, если сохранять текущие дополнительные экраны

- Приглашение, согласие, список нескольких подопечных и снятие защиты: сейчас Никита связан с Марией демоданными; другие подопечные хранятся локально, ссылки приглашений демонстрационные.
- Прямой перевод от Никиты Марии: существующее создание перевода рассчитано на защищённый аккаунт. Если этот экран станет частью демо, понадобится отдельная серверная операция с проверкой прав и баланса отправителя.
- Сброс из Help: сейчас для репетиции используется свежая демосхема. Для кнопки нужен отдельный сброс, ограниченный деморежимом.
- Push или отправка ссылок за пределы приложения: заявки на одобрение обновляются внутри открытого Expo; сохранение денежного запроса само по себе не отправляет сообщения и не создаёт ссылку для оплаты.
- Текущие элементы интерфейса для IBAN, Scam Pause, ручных избранных, отключения порога, карт и регулярных платежей в согласованный MVP не входят.
