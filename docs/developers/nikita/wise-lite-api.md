# WiseEASE API

Контракт Spring Boot для подключения Expo. Базовый адрес для локального демо `http://localhost:8080`. Деньги в EUR, JSON-числа с максимум двумя десятичными знаками. Время передаётся в миллисекундах Unix. Каждый запрос кроме входа использует `Authorization: Bearer <token>`.

| Метод и путь | Тело или параметры | Успешный ответ |
| --- | --- | --- |
| `POST /auth/login` | `{ "email": "maria@example.com", "password": "…" }` | `200 { token, account }`. `account` содержит `id`, `wiseId`, `name`, `role`. Роли `owner` и `helper`. |
| `POST /auth/logout` | Без тела | `204`. Токен больше не действует. |
| `GET /state` | Без тела | `200` со снимком состояния. |
| `POST /household/connect` | `{ "helperWiseId": "trusted-person" }` | `200 { state }`. Вошедший владелец сразу подключает существующий аккаунт помощника. |
| `GET /recipients/lookup?wiseId=anna` | Точный Wise ID | `200 { id, wiseId, name }`. |
| `POST /transfers/preview` | `{ "recipientId": "anna", "amount": 600 }` | `200 { "reasons": ["ABOVE_THRESHOLD", "NEW_RECIPIENT"] }`. |
| `POST /transfers` | То же тело, плюс `expectedReasons` из предпросмотра. Заголовок `Idempotency-Key` обязателен. | `200 { id, state }`. |
| `POST /transfers/to-protected-account` | `{ "amount": 50 }`, заголовок `Idempotency-Key` обязателен. | `200 { id, state }`. Помощник переводит собственные деньги своему подопечному; получателя определяет сервер. |
| `POST /transfers/{id}/decision` | `{ "approve": true }` или `false` | `200 { state }`. Доступно назначенному помощнику. |
| `PUT /settings/limit` | `{ "limit": 250 }` | `200 { state }`. Доступно помощнику. |
| `PUT /settings/rules/{rule}` | `{ "enabled": false }`, где `rule` — `limit` или `checkNew`. | `200 { state }`. Помощник планирует отключение через 24 часа. `true` включает правило сразу и отменяет запланированное отключение. |
| `PUT /settings/request-people` | `{ "accountIds": ["nikita", "anna"] }` | `200 { state }`. Помощник заменяет список целиком. |
| `POST /money-requests` | `{ "recipientId": "nikita", "amount": 25 }` | `200 { id, state }`. Прототип сохраняет запрос и показывает подтверждение Марии. |
| `POST /demo/reset` | Без тела | `200 { state }`. Только для Марии и Никиты в деморежиме. |

## Снимок состояния

`GET /state` возвращает `{ account, ownerId, balance, accountBalance, limit, checkNew, protectionOffAt, transfers, recipients, requestPeople }`. `accountBalance` — собственный баланс вошедшего аккаунта. `balance` — баланс защищаемого счёта. Для помощника он равен `null`. Помощник видит историю и настройки семьи. `recipients` и `requestPeople` — массивы `{ id, wiseId, name }`. Первый формируется из успешных переводов. Второй задаёт помощник, а приложение Марии читает его при обновлении состояния. `limit` и `checkNew` показывают действующие правила: `limit` равен `null`, когда проверка порога выключена. `protectionOffAt` содержит только предстоящие отключения, например `{ "checkNew": 1794704400000 }`.

Операция содержит `id`, `direction` (`incoming` или `outgoing`), `recipient`, `sender` (для входящих), `amount`, `status`, `createdAt`, `expiresAt`, `expired`, `approvalReasons`, `aboveLimit`, `isNew` и `limitAtCreation`. Входящие операции содержат только завершённые зачисления. Статусы исходящих операций — `sent`, `pending`, `approved`, `declined`. `approved` означает, что списание и зачисление уже завершены в БД. Операция после истечения срока возвращается как `declined` с `expired: true`.

Для синхронизации при подключении клиент может применять `state` из ответов и читать `GET /state` раз в 1,5 секунды в активном приложении, а также при возврате к нему.

## Правила и ошибки

- Подключение устанавливает порог 250 €, проверку новых получателей и добавляет помощника в список для денежных запросов. Повтор с той же парой сохраняет настройки; если один из аккаунтов уже связан с другим, сервер возвращает `409`. Самоподключение даёт `400`, отсутствующий или не имеющий входа аккаунт помощника — `404`.
- Прямой перевод не требует одобрения и появляется как входящий перевод в истории подопечного. В ответе помощника остаётся собственный баланс и история семьи. Не назначенный помощник получает `403`.
- Сброс восстанавливает исходные демобалансы, правила и историю, очищает денежные запросы Марии и сохраняет сессии. Если демоданные неполные или связаны переводами с другими аккаунтами, он возвращает `409`.

- Одобрение требуется при сумме строго выше порога или при включённой проверке и отсутствии предыдущего успешного перевода получателю. Обе причины могут сработать вместе. Выключение каждого правила действует на новые переводы через 24 часа. Повторное отключение не сдвигает срок. Ранее созданные заявки продолжают ждать решения.
- `pending` действует 12 часов с создания. Деньги остаются на счёте до одобрения. При отказе и истечении срока балансы не меняются. При одобрении Spring повторно проверяет остаток и проводит списание, зачисление и решение в одной транзакции.
- Повтор создания с тем же аккаунтом, ключом, получателем и суммой возвращает существующий ID. Смена суммы или получателя с тем же ключом возвращает `409`. Если причины изменились между предпросмотром и созданием, клиент получает `409` и заново показывает причины.
- Ошибка WiseEASE содержит `{ "error": "message" }`. `400` означает неверный ввод, недостаток средств или недоступного получателя денежного запроса, `401` — ошибку входа или сессии, `403` — действие вне прав роли, `404` — неизвестный Wise ID или недоступный перевод. `409` также используется для уже решённой или просроченной заявки.

Способы запуска, демоаккаунты и проверки описаны в [инструкции бэкенда](../../../backend/README.md).
